Mechanism 1. training_features.tif declares its nodata as -3.4028234663852886e+38 (the float32 minimum), not NaN, and 3,061 of those sentinel pixels sit inside the scoring footprint. Any pipeline that reads the bands without replacing the sentinel ships values near −3.4×1038, which is not in [0, 1].

Mechanism 2. The feature raster's valid region is smaller than the submission template's. A footprint mask taken from a feature band (5,165,852 px) instead of from example_submission.tif (5,167,373 px) strands exactly 3,061 scored pixels as NaN. NaN fails any ((v >= 0) & (v <= 1)).all() check.

This writer takes its footprint from the template, writes zeros (not NaN) outside it, and re-reads the file from disk before declaring success.

Is this file worth a weekly slot?

Honest answer: unknown, and no local instrument can answer it. The holdout this repository can compute returns exactly 0.0 for this file, because the file is pruned 2 px from the catalogue and the holdout's truth is the catalogue. The same-catalogue holdout is measured to be anti-correlated with the live board (ρ = -0.857, p = 0.0065) across eight hash-pinned artifacts, so a low value there is not evidence against the file. What the local evidence does support:

  • the emission budget (40,000 px) sits inside the 37,654–44,090 px band that every 0.26–0.28 artifact in the group ledger occupies;
  • the ribbons recover 36.6% of withheld fault segments within 300 m against 2.6% for random lines — a 13.9× enrichment, rising to 45× for basin-interior segments, which is the lane's actual claim;
  • the file is unique against every cross-lane registry raster.

No projection is written as a score anywhere on this site.
