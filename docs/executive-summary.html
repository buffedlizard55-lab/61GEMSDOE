Why the "Predicted values must be in range [0, 1]" error cannot happen with this file

That error has two causes, both engineered out here and both re-checked against the bytes on disk: (1) the GeoDAWN feature raster's float32 sentinel -3.4028234663852886e+38 leaking into the prediction, and (2) a footprint mask derived from a feature band leaving 3,061 scored pixels as NaN. This file is written by gems61.submission_writer.write_submission, which refuses to write anything that is not already finite and inside [0, 1], then re-reads the TIFF from disk and aborts unless every one of the 12,279,160 cells passes.
