How to make a submission — exactly, step by step

The file to upload is here:

Steps

  1. Open the submission page. Go to the competition submission page (DrivenData, competition 306) and choose New submission.
  2. Click File to submit → Choose file. Select gems61-h61w-p60-dip-projected-basement-step-16894dots-20261011T155602Z-zeros.tif — or the .zip, which contains that one TIFF and nothing else. Do not rename it; the filename is the submission name the leaderboard records.
  3. Paste the note. Into Note (optional) paste, verbatim:
    H61-W buried-structure lane: Parker/Oldenburg basement steps from isostatic gravity, dip-projected to the surface trace; dots, catalogue-pru
    (140 of the 140 characters allowed.)
  4. Submit. The uploader validates the grid before scoring: same CRS, same shape, same geotransform as sample_submission.tif, single band, float32, values in [0, 1]. This file satisfies all of them.
  5. Read the score honestly. The number that comes back is ORGANIZER-CONFIRMED and is the only real score. Everything on this site is HOLDOUT-DTI — an index from this repository's own instrument — or a USER-REPORTED value from the group's sites. A projection is never a score.

If the uploader says “Predicted values must be in range [0, 1]”

That message means the raster contains at least one value that is not a number in [0, 1] — almost always NaN outside the survey footprint, which is how the competition's own problem statement describes the outside-the-bounds area (“data outside the bounds is null or nan”), but which this uploader rejects. Use a -zeros file: 0.0 outside the footprint, 0.0 everywhere with no fault, 1.0 on a predicted fault. Two of the group's history files carry -nan in their names and can trip this check. This session's file is a zeros file; its validator receipt records n_nan = 0 and n_inf = 0 over the whole raster, not only inside the footprint.

IR-61-NAN-02 (this session): the upload error reported in this project's brief is evidence about the uploader, and it is recorded here as a user-reported receipt, not as an organiser statement.

What “safe to submit” means here, and what it does not

  • Safe = the bytes on disk pass the local validator against the organiser's own sample grid, and the dot field is not a copy of any earlier raster in the family registry. Locally validated is not organiser acceptance.
  • Recommended for a weekly slot? No. Verdict from the run card: negative: the dip projection did not beat its own unprojected ablation and/or random lines on the shared holdout.
  • Uniqueness is checked two ways — rank correlation of the soft surface (limit 0.90) and the fraction of dots within 3 px of one earlier raster (limit 0.70, with a lift over random of 3.0). This file: UNIQUE, worst coverage 0.9887.
  • Slots. Promotion to a real weekly slot is a separate selector step, inside the weekly cap on the submission page. This repository never spends a slot automatically.
