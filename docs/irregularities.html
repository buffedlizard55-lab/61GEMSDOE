Irregularities and limitations found this session

idseveritystatement
IR-61-LEAK-01highA gradient-boosted habitat model reached HOLDOUT-DTI 0.1599 and a canary AUC of 0.901, above the protocol's 0.90 leakage line. The leave-one-quadrant-out retest shows the AUC falls to 0.518–0.618 across all 16 blocked retests, with no training pixel inside the scored quadrant, and the DTI to the random baseline: the skill was adjacency to visible traces, not generalisation. The shipped file uses the L2 logistic model (canary AUC 0.626).
IR-61-PRUNE-01highThe catalogue prune has conflicting evidence. On the hide-and-recover holdout a 2 px prune beats 3 px (0.1599 vs 0.1458 for the same model) because the withheld truth is adjacent to visible traces. On the live metric the group's own controlled pair (gems25-dotted-h19-5-d2-8 0.2600 → gemsdoe32-h33-h33-2-b2 0.2778, an exact set difference deleting every dot within 3 px of the catalogue) says 3 px wins. The shipped file follows the live evidence (3 px) and the holdout cost is reported.
IR-61-BUDGET-01mediumThe holdout prefers more dots monotonically (random lines 0.0220 → 0.0434 from 20 k to 80 k), while the group's live ladder prefers ~38–40 k. The holdout's withheld-truth set is small and catalogue-adjacent, so it cannot see the false-positive mass that extra dots create against the full hidden fault population. Shipped at 40 k.
IR-61-MEM-01mediumThe development sandbox has ~3.9 GB of RAM and 2 cores. The 28-channel habitat stack (1.38 GB float32) is written channel-by-channel into a memmap and predictions are computed in 400 k-row chunks; an earlier version materialised all 19 bands as float64 and was killed by the OOM reaper. No result was lost.
IR-61-SCORE-01highEvery score attributed to the group's own files (0.2778, 0.2750, 0.2708, …) is an owner report on the group's pages. None is an organizer receipt linking those bytes to a leaderboard row. The public leaderboard rows belong to other teams.
IR-61-PROVENANCE-01highThe competition rasters come from a hash-pinned public GitHub mirror (buffedlizard55-lab/6GEMSDOE); the DrivenData data page is login-walled and unreachable from this sandbox. All three digests match the mirror's pins, but they are not organizer-authenticated.
IR-61-FOOTPRINT-01mediumThe 200 m inversion grid loses 24,274 footprint cells that the 100 m grid has (block means across the survey boundary are NaN). All correlations are taken on the common finite support and the erosion is reported in evidence/h61m_features.json.
IR-61-SRC-01highAn earlier session asserted that the competition ships a 1m_DEM_links.csv of 1 m DEM tile URLs. The hash-pinned bridge manifest (buffedlizard55-lab/6GEMSDOE@e2fe3f41…:data/bridge/manifest.json) lists exactly three files — gems-geodawn-numerical-features.tif, existing_faults.tif and example_submission.tif — so the claim is false and is corrected here and in evidence/h61g_hypotheses.json. The 1 m lidar hypothesis (H61-N) is unaffected in substance: USGS 3DEP is free public-domain data obtainable from The National Map (apps.nationalmap.gov/downloader); it simply has to be fetched from USGS, not from the organiser. drivendata.org is unreachable from this sandbox, so no direct check of the data tab was possible.
IR-61-NET-01mediumEgress admits only github.com, api.github.com, codeload.github.com, registry.npmjs.org, pypi.org and files.pythonhosted.org. usgs.gov, drivendata.org and the 3DEP S3 endpoint all fail, so no new external raster was fetched this session; the one named obtainable source (3DEP 1 m DEM) is listed as a next step, not claimed as used.
